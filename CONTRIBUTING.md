# Como contribuir

Obrigado por querer ajudar. Contribuições são bem-vindas: correções, melhorias, traduções e novos temas.

## Antes de começar
- Abra uma *issue* descrevendo o que quer mudar, principalmente para funcionalidades novas.
- Mantenha o estilo do código e rode os testes do servidor: `npm run servidor:teste`.
- Não inclua dados reais (logs, senhas, endereços de servidor, dados de empresas) em código, testes ou exemplos. Use dados fictícios.

## Licença das contribuições
O projeto usa **MIT com Commons Clause** (veja [`LICENSE`](LICENSE) e [`LICENCA-RESUMO.md`](LICENCA-RESUMO.md)).

Ao enviar um *pull request*, você declara que:

1. **É o autor** do que enviou, ou tem o direito de enviar, e o conteúdo não viola direitos de terceiros nem contém código de licença incompatível.
2. Sua contribuição é licenciada sob **a mesma licença do projeto** (MIT com Commons Clause).
3. Você concede ao autor do projeto uma licença **perpétua, mundial, gratuita e irrevogável** para usar, modificar, sublicenciar e distribuir a sua contribuição **sob qualquer licença**, inclusive uma licença comercial ou outra licença futura do projeto. Você continua dono do que escreveu.
4. Você assina cada *commit* com `Signed-off-by` (`git commit -s`), confirmando as declarações acima (Developer Certificate of Origin, <https://developercertificate.org/>).

Sem isso não dá para aceitar a contribuição, porque o autor precisa poder manter e licenciar o projeto como um todo.

## Segurança
Se achar uma falha de segurança, **não abra uma issue pública**. Fale com o autor em particular, usando a opção de relato privado de vulnerabilidade do GitHub (aba *Security*).
